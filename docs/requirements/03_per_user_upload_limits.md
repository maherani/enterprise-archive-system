# نیازمندی ۰۳: محدودیت سهمیه آپلود به ازای هر کاربر (Per-User Upload Limits)

## ۱. شرح نیازمندی (Problem Statement & Business Need)
در آرشیوهای متمرکز سازمان‌ها و بانک‌ها، کاربران مختلف با نقش‌های متفاوت (پرسنل عادی، اپراتورهای اسکن، کارشناسان ممیزی و سرپرستان دپارتمان) اقدام به ثبت و آپلود فایل می‌کنند. عدم کنترل سقف حجم فایل‌های ارسالی یا اعمال محدودیت‌های یکسان و سراسری برای همه افراد منجر به اشغال غیرمنطقی پهنای باند و منابع ذخیره‌سازی می‌گردد. سازمان نیازمند مکانیزمی منعطف بود تا بتوان سقف مجاز حجم آپلود هر تراکنش فایل را به صورت اختصاصی برای هر کاربر یا به تفکیک نقش تعریف کرد و در صورت تخطی از این سقف، پیش از هدررفت منابع، درخواست آپلود در همان مرحله آغازین با خطای شفاف مسدود شود.

## ۲. نیازمندی‌های تابعی (Functional Requirements)
* **تنظیم سهمیه اختصاصی هر کاربر:** امکان تعیین سقف حجم آپلود به صورت اختصاصی برای هر نام کاربری بر حسب مگابایت، گیگابایت یا نامحدود.
* **ذخیره‌سازی استاندارد تنظیمات:** ذخیره سقف کاربر در جدول `oc_preferences` با کلیدهای `appid = 'archive_autotag'` و `configkey = 'upload_limit_bytes'`.
* **کنترل سخت‌گیرانه پیش از آپلود (Pre-Upload Check):** مسدودسازی درخواست‌های بزرگتر از حد مجاز با پرتاب استثنای خطای ۴۰۳ یا ۴۱۳ پیش از نوشتن داده روی دیسک.
* **دستورات مدیریتی خط فرمان (CLI):** دستور `occ archive:user:limit [uid] [limit]` جهت استعلام، تنظیم و حذف محدودیت کاربران.
* **پشتیبانی از کلاینت‌های وب و WebDAV:** اعمال محدودیت یکپارچه بر تمامی روش‌های ارسال فایل (پرتال وب، درگاه وب‌دَو و APIهای OCS).

## ۳. نیازمندی‌های غیرتابعی (Non-Functional Requirements)
* **پاسخ‌دهی سریع:** ارزیابی سهمیه کاربر در کسری از میلی‌ثانیه بدون ایجاد تاخیر در لود فایل‌سیستم.
* **انعطاف‌پذیری واحدهای حجم:** پشتیبانی از دریافت مقادیر عددی همراه با واحدهای متداول (مانند `500M`, `2G`, `unlimited`).
* **عدم ایجاد اختلال در سهمیه کلی اکانت (Storage Quota):** تفکیک کامل بین سقف حجم یک فایل آپلودی (Per-File Upload Limit) و سهمیه کلی کل پوشه کاربر (Account Storage Quota).

## ۴. معماری و مدل مفهومی (Architectural & Conceptual Model)
معماری این کنترل بر پایه شنونده رویداد `BeforeNodeWrittenListener` و سرویس متمرکز `UploadLimitService` پیاده‌سازی شده است:

```
+───────────────────────────────────────────────────────────+
|         Upload Request (Web Browser / WebDAV Client)      |
+───────────────────────────────────────────────────────────+
                              │
                              ▼
+───────────────────────────────────────────────────────────+
|  BeforeNodeWrittenListener (OCA\ArchiveAutoTag\Listener)  |
+───────────────────────────────────────────────────────────+
                              │
                              ▼
+───────────────────────────────────────────────────────────+
|  UploadLimitService (OCA\ArchiveAutoTag\Service)          |
|  - Fetch user limit from oc_preferences                   |
|  - Check incoming file size against threshold             |
+───────────────────────────────────────────────────────────+
         │                                         │
         │ [حجم فایل > سقف مجاز]                   │ [حجم فایل <= سقف مجاز]
         ▼                                         ▼
+───────────────────────────────────+     +───────────────────────────────────+
|  پرتاب Sabre\DAV\Exception        |     |  مجوز ادامه نوشتن روی دیسک         |
|  یا SecurityPermissionException   |     |  و شروع تراکنش استوریج            |
+───────────────────────────────────+     +───────────────────────────────────+
```

## ۵. رفتار پیش‌فرض Nextcloud و شکاف موجود (Nextcloud Default Behavior vs Custom Need)
در نسخه استاندارد، پارامتر سقف حجم آپلود (`upload_max_filesize`) مقداری ثابت در پیکربندی PHP سرور برای تمامی کاربران سامانه است و امکان تفکیک سقف حجم فایل ارسالی به ازای هر نام کاربری وجود ندارد. این شکاف با توسعه سرویس `UploadLimitService` رفع شد.

## ۶. رویکردهای بررسی‌شده و دلایل رد گزینه‌های نامناسب (Trade-offs & Rejected Alternatives)
* **رویکرد اول: استفاده از سهمیه پیش‌فرض کاربر (User Quota):**
  * *علت رد:* سهمیه کاربری Nextcloud کل فضای اشغال‌شده اکانت را محدود می‌کند، نه سقف حجم یک تک‌فایل در یک آپلود خاص.
* **رویکرد دوم: محدودسازی سمت کلاینت با جاوااسکریپت:**
  * *علت رد:* این رویکرد به راحتی توسط فراخوانی‌های مستقیم WebDAV یا اسکریپت‌های اتوماسیون دور زده می‌شد و فاقد امنیت بود.
* **رویکرد برگزیده: اتصال به رویداد BeforeNodeWritten در لایه سرور:**
  * *مزیت:* امنیت ۱۰۰٪ تضمین‌شده در عمق لایه هسته و پشتیبانی از تمامی کلاینت‌های رسمی و غیررسمی.

## ۷. مدل داده و تغییرات پایگاه داده (Data Model & Schema Evolution)
استفاده هوشمندانه از جدول پیش‌فرض `oc_preferences` بدون نیاز به ایجاد جداول اضافی:
* `userid`: نام کاربری هدف (مانند `archive_user1`).
* `appid`: مقدار ثابت `archive_autotag`.
* `configkey`: کلید `upload_limit_bytes`.
* `configvalue`: سقف مجاز بر حسب بایت به عنوان عدد صحیح بزرگ.

## ۸. ساختار کد و فایل‌های پیاده‌سازی (Code Structure & File Breakdown)
* **سرویس اعتبارسنجی محدودیت آپلود:**
  * `apps/archive_autotag/lib/Service/UploadLimitService.php`: متدهای `getUserUploadLimit`، `setUserUploadLimit`، `checkUploadAllowed`.
* **شنونده رویداد پیش از نوشتن:**
  * `apps/archive_autotag/lib/Listener/BeforeNodeWrittenListener.php`: متصل به رویداد `OCP\Files\Events\BeforeNodeWrittenEvent`.
* **دستور مدیریتی خط فرمان:**
  * `apps/archive_autotag/lib/Command/UserLimitCommand.php`: کنترلر فرمان `archive:user:limit`.
* **اسکریپت تست و اعتبارسنجی:**
  * بخش تست سهمیه در `tests/test_dynamic_archive_system.py` (Step 6).

## ۹. هوک‌ها، ایونت‌ها و نقاط اتصال به هسته (Hooks, Events & Integration Points)
* ثبت شنونده در `BeforeNodeWrittenEvent` برای ارزیابی حجم فایل در بدو ورود.
* استفاده از `IConfig` هسته Nextcloud برای تعامل سریع با تنظیمات ترجیحی کاربر.

## ۱۰. منطق گام‌به‌گام پردازش (Detailed Flow / Algorithm)
۱. جریان داده فایل وارد وب‌سرور می‌شود.
۲. لیسنر `BeforeNodeWrittenListener` فعال شده و مشخصات فایل ورودی و کاربر ارسال‌کننده را استخراج می‌کند.
۳. سرویس `UploadLimitService` سقف حجم تعریف‌شده برای کاربر را از دیتابیس استعلام می‌کند.
۴. اگر سقف تعیین شده باشد و حجم سند بیشتر از آن باشد، استثنا پرتاب شده و فرآیند انتقال فوراً لغو می‌گردد.
۵. در صورت مجاز بودن حجم، فایل بدون هیچ‌گونه سربار اضافی بر روی استوریج ذخیره می‌شود.

## ۱۱. وابستگی‌ها و پیش‌نیازها (Dependencies & Prerequisites)
* استقرار کامل اپلیکیشن `archive_autotag`.
* دسترسی ادمین جهت تنظیم حدود کاربران از طریق CLI.

## ۱۲. مدیریت خطا و سناریوهای استثنا (Failure Modes & Edge Cases)
* **کاربر فاقد سقف مشخص:** در صورتی که سقفی برای کاربر تعریف نشده باشد، سقف پیش‌فرض سامانه ملاک عمل خواهد بود.
* **فایل‌های با حجم صفر بایت:** آپلود فایل‌های مجاز با حجم صفر یا بسیار کوچک بدون ممانعت انجام می‌پذیرد.

## ۱۳. دسترسی‌ها، نقش‌ها و امنیت (Security, Roles & Permissions)
* مدیر سیستم (`admin`): معاف از محدودیت‌های حجمی و دارای اختیار کامل در تخصیص سهمیه سایرین.
* سایر پرسنل: ملزم به رعایت سقف تعیین‌شده توسط سرپرست سیستم.

## ۱۴. APIها و پروتکل‌ها (APIs & Protocols)
* **فرمان تعیین سقف کاربر:**
  ```bash
  docker compose exec -u www-data app php occ archive:user:limit archive_user1 100M
  ```
* **فرمان استعلام سقف کاربر:**
  ```bash
  docker compose exec -u www-data app php occ archive:user:limit archive_user1
  ```
* **فرمان رفع محدودیت کاربر:**
  ```bash
  docker compose exec -u www-data app php occ archive:user:limit archive_user1 unlimited
  ```
